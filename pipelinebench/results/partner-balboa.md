# Design partner: datacoves/balboa (dbt on Snowflake, TaskFlow Airflow)

[datacoves/balboa](https://github.com/datacoves/balboa) is Datacoves' public demo platform: 43 dbt models on
Snowflake, 12 sources, 5 seeds, and Airflow DAGs written with the TaskFlow API (`@dag`, `@task`, `@task_group`),
many generated by cartage. It is the second real platform after cal-itp, and the first without a published manifest:
the manifest here comes from `dbt parse` with the packages pinned in `package-lock.yml`, so there is no compiled SQL
and Fathom reads each model's raw SQL.

## Sync

| | before | after |
| --- | --- | --- |
| models whose columns could not be read | 7 of 43 | 1 (a semantic view, which is not SQL) |
| Airflow DAGs / tasks | 0 / 0 | 32 / 53 |
| tasks linked to the dbt models they build | 0 | 4 tasks, 14 links |

What failed before:

- `ref('stg_country_populations', v='2')`: a versioned ref was left as Jinja.
- `from {{ this }}` inside `{% if is_incremental() %}` was removed, leaving `from )`.
- A macro as an expression (`invoice_date <= {{ trailing_edge_month() }}`) or as a whole CTE body
  (`month_spine as ({{ procurement_month_spine() }})`) was removed, leaving invalid SQL. Expressions now read as
  `null` and a CTE body as `select null`, so the rest of the model keeps its lineage. A column that comes only from such
  a CTE is reported per column, not guessed.
- The adapter only knew `DAG(...)`. Every balboa DAG is a `@dag` function.
- `dbt build -s 'tag:daily_run_airbyte+ tag:daily_run_fivetran+'` is one quoted argument holding two selectors,
  and both tags are on sources, not models.

## Review of 15 recent commits, deterministic only

The last 15 commits that touch `transform/` or `orchestrate/dags/`, mostly regenerated cartage DAGs. 13 are `inform`
with nothing unresolved. Two are `warn` because a project-level file is not mapped to models, and both now say why:
`dbt_project.yml` (project configuration) and `package-lock.yml` (a package upgrade can change any macro the models call).

## Rerun

```
git clone https://github.com/datacoves/balboa && cd balboa/transform
# install the packages in package-lock.yml (dbt deps, or git clone each at its tag into dbt_packages/)
dbt parse   # any Snowflake profile; parse does not connect
cd .. && cat > fathom.yaml <<'YAML'
db: .fathom/graph.duckdb
adapters:
  dbt: {project: transform}
  airflow: {dags: orchestrate/dags}
  git: {paths: [transform, orchestrate/dags], max_commits: 500}
YAML
fathom sync
```
